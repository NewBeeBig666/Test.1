## 1. 封面图片补充

### 1.1 数据源与实测结果

| 域 | 封面来源 | 实测 |
|---|---|---|
| 图书 | BX 数据集 Image-URL-M（Amazon 图片 CDN） | 抽样 20/20 存活；缺失/失效可后台补 URL |
| 电影 | **IMDb Suggestion API**（免 key：`v3.sg.media-imdb.com`，响应含海报 CDN URL 与 width/height 元数据） | 批量预取进行中，已落地 350+ 张（如 Jumanji 1131×1500px） |
| 课程 | Udemy 封面 CDN 服务器端 403（无公开封面 API）→ **类目矢量图标封面**（前端绘制） | 无限分辨率、零请求、无水印、比例完美 |

### 1.2 批量预取与质量审核（fetch_covers.py）

- 标题归一化（"Matrix, The (1999)" → the matrix）→ IMDb 检索 → 标题精确匹配 + 年份校验 + `q=feature` 过滤
- **质量审核**：宽 ≥300px 且高/宽比例 ∈ [0.45, 1.8]（排除横幅/变形图），分辨率元数据来自 API 响应（无需下载即可审核）
- 审核结论与分辨率写入 `items_meta.csv`（poster_url/poster_w/poster_h/cover_ok，re-import 持久）并同步 MySQL `movie.poster_url`
- 断点续传（每 100 部落盘）；失败清单（外文/生僻标题）输出到 `reports_all/cover_audit.md` 供后台手动补充
- 运行：`py -3 fetch_covers.py`（全量，约 3650 部）或 `--popular 400`（热度优先）

### 1.3 自适应展示

卡片 `aspect-ratio: 3/4 + object-fit: cover`，抽屉 `object-fit: contain`；`loading="lazy"` 懒加载；加载失败回退域色渐变排版卡。CSS 矢量/响应式渲染保证任意 DPR 屏幕清晰。

## 2. 内容简介展示（enrichment）

### 2.1 架构（按需抓取 + MySQL 缓存）

```
ItemDrawer 打开 → GET /api/enrichment/{domain}/{itemId}
  → SpringBoot EnrichmentService：查 item_enrichment 表
     命中（含 manual）→ 直接返回（5~15ms）
     未命中 → FastAPI /api/enrich → OpenLibrary/IMDb/模板合成 → 落库缓存 → 返回
```

### 2.2 各域内容结构（sections）

| 域 | 段落 | 数据来源 |
|---|---|---|
| 图书 | 作者信息 / 内容摘要 / 推荐理由 | 元数据 + OpenLibrary Read API（不可达时回退合成并在 source 标注） |
| 电影 | 影片信息（上映/类型）/ 主演 / 剧情简介 / （后台可加 内容简介/推荐理由） | IMDb suggest（主演、海报）+ 元数据合成 |
| 课程 | 课程信息 / 学习目标 / 课程大纲 / 适合人群 / 讲师信息 | 课程元数据模板合成（Udemy 无公开简介 API） |

格式化展示：分卡片段落、label 高亮、来源徽章（OpenLibrary/IMDb/系统生成/管理员编辑 + 已缓存标记）。

### 2.3 外部链接（构造式，浏览器侧可达）

| 域 | 链接 |
|---|---|
| 图书 | OpenLibrary 阅读页（ISBN）+ Amazon 购买搜索 |
| 电影 | IMDb 详情页（links.csv imdbId） |
| 课程 | Udemy 官方课程页（数据集 url 列，已入 course.source_url） |

**安全机制**：`window.open(url, '_blank', 'noopener,noreferrer')` + 跳转前确认对话框（ElMessageBox，显示目标 URL）。

## 3. 管理后台（/admin，admin 账号）

- **富化记录列表**：三域分页表格（封面/来源/人工/链接检查/更新时间）
- **手动编辑**（PUT /api/admin/enrichment）：封面 URL、内容简介、推荐理由、外部链接列表；保存后 `manual=true`，**不会被自动抓取覆盖**；编辑保留自动段落仅覆盖对应 label
- **删除**：清除缓存，下次访问重新抓取
- **封面覆盖扫描**：三域缺失统计（books 0/9085、movies 报告预取缺口、courses 矢量封面）
- **链接检查**：手动抽查（HEAD 3s 超时，200-399 为可访问）+ **每日 04:30 定时抽查**（@Scheduled），结果写入 checked_at/check_ok 展示在列表

权限：`/api/admin/**` 要求用户名 `admin`（毕设简化，生产应换 RBAC 角色模型）；前端导航对 admin 显示"管理"入口（响应式）。

## 5. 性能验证（本机实测，3 次取最优）

| 接口 | 耗时 | 说明 |
|---|---|---|
| 首页图书推荐（n=12） | 46.1 ms | 与优化前同级（无新增请求） |
| 首页电影推荐（n=12，含海报 URL） | 27.4 ms | 海报 URL 来自 DB 字段，零额外 RTT |
| 列表检索 /items | 25.6~30.6 ms | 不变 |
| 详情富化（缓存命中） | 5.5~15.6 ms | 新增功能 |
| 详情富化（首次抓取） | ~0.6-1.4 s | 一次性成本，之后永久缓存 |

**结论**：列表/推荐链路未新增任何请求（封面 URL 为 DB 字段透传），页面加载速度无回退；新增的简介为详情页按需请求且缓存后毫秒级。前端构建产物 167KB（gzip 64KB）与上一版基本持平。

## 6. 已知限制（如实说明）

1. OpenLibrary / Wikipedia / Wikidata 在服务器网络不可达 → 图书简介回退合成 + 管理后台手动补充；适配器已实现，网络可达（或配置代理）时自动升级为真实简介
2. Udemy 封面 CDN 与课程页对服务器端返回 403 → 课程用矢量封面；Udemy 外链对用户浏览器仍有效（链接检查的失败项含此说明）
3. IMDb suggest 未匹配的电影（外文/生僻标题）无海报，回退渐变卡并列入 cover_audit.md 待后台补充
4. 管理员判定为用户名 `admin`（毕设简化）

### 8.5 探索流全球均衡算法（第五轮调整）

**原缺陷**：区域条目一次性注入（`ri++` 单向推进），电影/图书区域精选约 6 页后耗尽，后续页面全为主目录；区域列表整体 shuffle 无配额，页内区域分布不均；课程域中国课程无配额仅随机混入。

**均衡轮转算法**（`ItemService.discovery()`）：

- 区域池按来源分组（电影 6 池 / 图书 6 池 / 课程=中国课程单池），各池日种子洗牌，轮转次序日种子随机（当日稳定、每日轮换）
- 分组交错注入：电影/图书 `[区域×2 + 主目录×1]`、课程 `[中国×1 + 国际×5]`；区域池**循环复用**（用尽从头再取），主目录顺序推进直至耗尽
- **恒定配额**：电影/图书任意页 = 六区域各 2 条 + 主目录 6 条（区域占 2/3）；课程任意页 = 中国 3 + 国际 15；实测第 1/50(100)/200(500) 页分布完全一致
- totalElements = 物化序列长（电影 ~3×主目录，翻页全程均衡）；主目录全量可达（电影第 608 页内全覆盖）
- 去重：课程区域池为 course 表国内平台条目（`isCnPlatform`），主目录 `removeAll` 去重

### 8.7 微信读书跳转乱码修复（第七轮，2026-09）

**现象**：图书条目选择"微信读书"跳转后目标页面乱码。

**根因分析**：
- 微信读书网页版无公开搜索结果页路由，原链接 `weread.qq.com/web/search/global?keyword=` 实为 **XHR 数据接口**——浏览器直接打开渲染原始 JSON
- 该接口响应无 charset 声明，浏览器按本地默认编码解码：国产双核浏览器（QQ/360 等）默认 GBK 解码 UTF-8 字节 → 中文乱码；Chrome 默认 UTF-8 → 表现不一，属典型跨浏览器编码差异问题
- 涉及代码定位：`enrichment.py` `_links_books`（抽屉外链生成）、`AwayView.vue` CN_SITES（/away 国内选项生成）

**修复方案（后端代理重定向）**：
- 新增 `WereadController`：`GET /api/weread?q={书名}`（免鉴权白名单）服务端检索微信读书搜索接口（`HttpClient` + UTF-8 显式解码 + Jackson 解析），取首个结果 `deepLink`（书籍详情页，正常 HTML）**302 重定向直达**；无匹配/异常回退微信读书主页；结果内存缓存
- `enrichment.py` 与 `AwayView.vue` 的微信读书链接统一改为 `/api/weread?q={percent-encoded 书名}`（同源相对路径，无 CORS）；/away 页 `isCnUrl` 识别代理路径并置顶显示"微信读书 · 直达书页"

**浏览器兼容性**：本环境为 Chromium 内核内置浏览器（已实测端到端链路：抽屉 → /away 默认高亮 → 点击 → 《三体》直达书籍详情页正常中文渲染，无 JSON 直显/乱码；英文无匹配书回落主页正常）。Chrome/Firefox/Safari/国产浏览器无法在本环境逐一实测，但修复后链路完全标准化：URL 参数 RFC 3986 percent-encoding（UTF-8）、HTTP 302 标准重定向、目标为自带 charset 声明的正常 HTML 页面——不再依赖浏览器对无 charset 响应的本地编码猜测（乱码的跨浏览器差异根源已消除）。平台自身响应均为 UTF-8 + charset 声明（SpringBoot JSON / index.html meta）。

### 8.9 作品点击交互统一（右侧抽屉详情，第九轮，2026-09）

**原状**：区域公版图书（world_content 负 ID）点击直接经 /away 跳转外部网站，与其他作品（抽屉详情）不一致。

**改造**：

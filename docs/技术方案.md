> 本科软件工程毕业设计 · 优化改造版技术方案
> SpringBoot 3.2 + FastAPI + MySQL + Redis + Vue 3 + Element Plus

## 1. 系统概述

### 1.1 改造目标

| 维度 | 改造前 | 改造后 |
|---|---|---|
| 推荐域 | 仅图书（Book-Crossing 单域） | 图书 / 课程 / 电影三域统一 |
| 算法 | UserCF / ItemCF / ContentBased / MostPopular | 四算法 + **CrossDomain 跨域推荐**（统一 TF-IDF 标签空间桥接） |
| 用户体系 | 前端输入数字用户ID切换 | 注册 / 登录（Redis 会话令牌）+ 数据集"体验用户"入口 |
| 行为采集 | 仅图书域 view/click | 三域 view / click / rating / favorite，评分后自动触发模型增量重训 |
| 用户画像 | 单域兴趣标签 | **跨域统一画像**（三域兴趣融合）+ 分域画像 + 行为时间线 |
| 前端 | 原生 HTML/JS 三 Tab 静态页 | Vue 3 SPA，苹果官网级设计（毛玻璃导航/大标题 hero/卡片悬浮/响应式） |
| 评估 | 单域 4 算法对比 | 三域 × 4 算法 + 跨域模拟实验 + 跨域词表重叠度分析 |

### 1.2 总体架构

```
┌────────────────────────────────────────────────────────────┐
│  Vue 3 SPA（Vite 构建产物由 SpringBoot 静态服务，8080）        │
│  登录/注册 · 首页三域推荐 · 三域检索 · 画像 · 算法实验室         │
└──────────────┬─────────────────────────────────────────────┘
               │ /api/**（axios + Bearer Token）
┌──────────────▼─────────────────────────────────────────────┐
│  SpringBoot 3.2（8080）业务后端                               │
│  AuthInterceptor 会话鉴权 · ItemService 统一三域检索          │
│  RecommendService（Redis 缓存 rec:{domain}:{algo}:{uid}:{n}）│
│  EventService（MySQL 落库 + 转发算法 + 评分后异步重训）        │
├──────────────┬─────────────────────────────────────────────┤
│  MySQL recsys │  Redis（token 会话 24h + 推荐缓存 30min）     │
│  user/book/   │                                              │
│  course/movie/│                                              │
│  behavior_event                                              │
└──────────────┬─────────────────────────────────────────────┘
               │ RestTemplate（2s 连接 / 10s 读超时）
┌──────────────▼─────────────────────────────────────────────┐
│  Python FastAPI（8001）算法服务                               │
│  三域模型（UserCF/ItemCF/ContentBased/MostPopular）           │
│  CrossDomain（全局统一 TF-IDF 空间，三域行为 → 目标域推荐）    │
│  data/processed_real|movies|courses + processed_global       │
└─────────────────────────────────────────────────────────────┘
```

### 1.3 关键设计决策

1. **三域用户不重叠 → 跨域走内容侧桥接**：三个公开数据集的用户群体互不重叠，无法做跨域协同过滤。本系统将三域全部物品文本（书名+作者+出版社 / 片名+类型+年份 / 课程名+难度+类目）投入**同一份 TF-IDF 词表**（`preprocess_global.py`，14940 物品 × 17315 共享词，含 love/history/python 等跨域共现词），用户在任意域的行为加权合成统一画像向量，即可对目标域物品做余弦排序——图书行为可以直接推荐电影。
2. **注册用户 ID 从 1e9 起**：与数据集用户 ID（< 3×10^5）空间隔离；算法侧以 `online_user_map.csv` 为每个线上用户在各域分配内部 ID，修正了改造前"行为用户 ID 与内部 ID 冲突覆盖"的缺陷。
3. **评分事件自动重训**：用户提交评分（显式反馈）后，后端异步调用算法服务 `POST /api/reload`（三域重训约 2 秒），行为即时影响推荐，形成"评分 → 重训 → 推荐"闭环；Redis 缓存按用户维度淘汰保证不返回旧结果。
4. **评分归一化修正**：rating 事件使用真实评分（1-5 星 → 0.2~1.0），替代改造前固定权重忽略评分值的做法。

### 2.1 数据集总览

### 2.3 统一预处理流程（三域一致）

```
原始数据 → 5-core 迭代过滤（用户/物品至少 5 条交互）
        → 去重 → 连续整数 ID 重编码（user_id / item_id）
        → 评分 Min-Max 归一化（rating_norm ∈ [0,1]，三域可比）
        → 8:2 分层划分（random_state=42，按 user_id 分层）
        → TF-IDF 内容特征（title+subtitle+extra，min_df=2，(1,2)-gram，去停用词）
输出 ratings_{all,train,test}.csv / items_meta.csv / item_tfidf.npz / item_vectorizer.joblib
```

脚本：图书 `preprocess.py`；电影/课程 `preprocess_domain.py`；跨域全局空间 `preprocess_global.py`（global_id = 域偏移 1e8/2e8/3e8 + item_id 防冲突）。

## 3. 推荐算法方案

### 3.1 算法清单（`algorithms.py`，统一接口 `fit(ratings_df)` / `recommend(user_id, n)`）

| 算法 | 原理 | 复杂度/实现要点 |
|---|---|---|
| UserCF | score(u,i) = Σ sim(u,v)·r(v,i)，Top-20 余弦近邻用户 | sklearn NearestNeighbors 余弦 KNN 图，稀疏矩阵加权汇总 |
| ItemCF | score(u,i) = Σ sim(i,j)·r(u,j)，Top-20 近邻物品 | 评分矩阵转置建 KNN 图，用户交互物品的近邻加权加分 |
| ContentBased | 用户画像 = 交互物品 TF-IDF 加权平均；推荐 = 画像×物品余弦 | 冷启动友好，可解释（画像即兴趣标签） |
| CrossDomain | **统一空间桥接**：三域行为 → 统一画像 → 目标域余弦 Top-N | 依赖 `preprocess_global.py` 的全局 TF-IDF；过滤已交互 |
| MostPopular | 全局交互量排序 | 冷启动兜底 + 实验下界参照 |

### 3.2 跨域推荐（论文亮点）

```
用户 u 在三域的行为 {(domain, item_id, weight)}
   → weight × global_tfidf[行] 加权求和 → L2 归一化 → 统一画像 p(u)
   → score(i) = cos(p(u), 全局物品向量) ，仅保留目标域物品
   → 过滤已交互 → Top-N
```

全局空间可行性由词表重叠支撑：books∩movies 共有词 1162 个（Jaccard 0.054）、books∩courses 645 个；三域共有高频词（按全局 IDF）构成跨域信号通道。**线上注册用户**在三个模块的行为天然跨域——这是本机制的真实应用场景（首页/画像页/实验室"跨域推荐演示"均可体验）。

### 3.3 评估实验设计（`evaluate_all.py`）

- **指标**：Precision@K / Recall@K / HitRate@K / NDCG@K / Coverage（K=10，每域抽样 ≤1000 用户）
- **统一正反馈阈值**：rating_norm ≥ 0.7（图书评分 ≥8/10、电影 ≥4.0/5、课程 ≥3.8/5，三域可比）
- **跨域模拟实验**（因数据集用户不重叠，无真实跨域测试集）：
  - CrossDomain-Sim：电影测试用户 × 统一空间中画像最相似的图书用户，嫁接其图书行为 → 推荐电影
  - CrossDomain-Random：随机配对图书用户（负对照）
  - 参照：单域 ContentBased（本人电影历史）/ MostPopular
- 结果见 `recommender/reports_all/report.md`（含各域最优算法结论与跨域解读）

## 4. 后端设计（SpringBoot，包 `com.recsys`）

### 4.1 模块划分

| 模块 | 类 | 职责 |
|---|---|---|
| 认证 | AuthController / AuthService / AuthInterceptor / UserIdHolder | 注册登录（SHA-256(salt+pwd)）、UUID 会话令牌（Redis TTL 24h，故障降级本地缓存）、/api/** 拦截鉴权、**匿名游客默认会话**（guest-auto：无会话访客自动分配 [2e9,3e9) 空间一次性 ID，免登录直通全站，行为照常采集参与个性化）、体验用户（数据集原始 ID） |
| 物品 | ItemController / ItemService | 统一检索 `/api/items?domain&q&category&page&size` 路由三张物品表，统一 DTO（itemId/domain/title/subtitle/extra/imageUrl/platform/price/subscribers/genres/year） |
| 推荐 | RecommendController / RecommendService / RecCache | 代理算法服务 + Redis 缓存（key 含 domain，响应含 fromCache/latency）+ 推荐结果物品富化 + 手动重训 |
| 行为 | EventController / EventService | 三域行为落库 MySQL + 转发算法服务 + 用户级缓存淘汰 + 评分后异步重训 + 历史查询（富化标题） |
| 客户端 | AlgoServiceClient | RestTemplate（连接 2s/读 10s），三域参数 + 跨域画像 + reload |

### 4.2 数据库（MySQL `recsys`，JPA ddl-auto:update + `import_to_mysql.py` 全量导入）

| 表 | 关键列 | 数据量 |
|---|---|---|
| sys_user | id(从1e9), username(唯一), password_hash, salt | 运行时注册 |
| book | item_id, isbn, title, author, publisher, image_url | 9,085 |
| course | item_id, title, level, category, platform, price, subscribers | 2,205 |
| movie | item_id, title, genres, year | 3,650 |
| behavior_event | user_id, item_id, domain(默认books), event_type, rating, created_at | 运行时采集 |

### 4.3 缓存与一致性策略

- 推荐缓存：`rec:{domain}:{algo}:{userId}:{n}`，TTL 30 分钟，Redis 优先 + 本地内存降级（Redis 故障 60s 内不再重试）
- 用户产生新行为 → `evictByUser`（按 `:{userId}:` 模式匹配删除）→ 下次推荐实时反映最新兴趣
- 评分事件 → 异步 `POST /api/reload`（三域重训约 2s）→ 行为闭环

## 6. 统一 API 规范

### 6.1 认证（免鉴权 `/api/auth/**`）

| 方法 | 路径 | Body/参数 | 说明 |
|---|---|---|---|
| POST | /api/auth/register | {username, password} | 注册，返回 {token, user}；用户 ID 从 1e9 起 |
| POST | /api/auth/login | {username, password} | 登录，返回 Bearer Token（Redis 24h） |
| POST | /api/auth/guest | {userId} | 体验用户（数据集原始 ID：图书 1~278858 / 电影 1~610 / 课程 10000~12499） |

## 7. 优化前后对比分析

### 7.1 功能与架构

| 项 | 优化前 | 优化后 |
|---|---|---|
| 推荐能力 | 1 域 4 算法 | 3 域 5 算法 + 跨域画像/推荐 |
| 用户模型 | 无账户体系，ID 手输 | 注册登录 + 会话令牌 + 体验用户双通道 |
| 行为闭环 | 行为仅手动 reload 后生效 | 评分 → 异步重训（~2s）→ 缓存淘汰 → 推荐更新 |
| 数据缺陷 | 行为用户 ID 与内部 ID 冲突覆盖评分；评分值被忽略 | 线上用户 per-domain 内部 ID 映射；评分真实归一化 |
| 物品数据 | 图书无封面/无课程/无电影 | 图书封面（Image-URL-M）、真实课程目录、电影全量 |
| 可观测性 | 延迟 | 延迟 + 缓存命中 + 冷启动标记（实验室页实时 A/B 对比） |

### 7.2 用户体验（界面）

| 项 | 优化前 | 优化后 |
|---|---|---|
| 信息架构 | 单页三 Tab 平铺 | 6 页 SPA：首页（hero+三域推荐）/ 三域馆 / 画像 / 实验室 |
| 视觉 | 默认浏览器样式、无设计系统 | 苹果官网级：毛玻璃导航、大标题分区、圆角卡片、灰白分区、充足留白 |
| 交互反馈 | 文字提示 | 抽屉式详情、星级评分、toast、悬浮动效、滚动渐入、路由过渡 |
| 适配 | 桌面固定 | 响应式（卡片网格/横滑区/间距随断点收缩） |
| 埋点 | 仅 view/click 两类按钮 | 曝光(view)/点击/评分/收藏四类，含域标签 |

### 7.3 算法效果（离线评估，K=10，详见 reports_all/report.md）

- 图书域最优：ContentBased（P@10=0.0216, HitRate=17.6%）
- 电影域最优：UserCF（P@10=0.2030, HitRate=72.1%，密度高协同过滤优势明显）
- 课程域最优：ItemCF（P@10=0.0774, HitRate=55.2%）
- 跨域模拟：CrossDomain-Sim（P@10=0.0066）较随机配对（0.0040）提升 65%，验证统一标签空间携带跨域偏好信号；与单域内容推荐（0.0322）的差距源于离线数据无真实跨域用户——线上注册用户的真实跨域行为是该机制的应用场景。

## 8. 部署与运行

### 8.1 环境要求

JDK 21 · Python 3.11（`py -3`）· Node.js 18+ · MySQL 5.7+（root/root@127.0.0.1:3306，库 recsys 自动建）· Redis（`tools/redis-server.exe`）· Maven（`tools/apache-maven-3.9.16`）

### 8.2 全流程命令（根目录执行）

```bat
:: 0) 依赖安装（首次）
cd frontend && npm install && cd ..
py -3 -m pip install -r recommender/requirements.txt pymysql

:: 1) 数据预处理（数据已就绪，重建时执行）
cd recommender
py -3 preprocess.py --data_dir ./data/raw_real --out_dir ./data/processed_real
py -3 preprocess_domain.py --domain movies
py -3 preprocess_domain.py --domain courses --seed 42
py -3 preprocess_global.py
py -3 import_to_mysql.py --all

:: 2) 离线评估（生成 reports_all/）
py -3 evaluate_all.py --k 10 --sample 1000

:: 3) 构建
cd ../frontend && npm run build && cd ../backend
..\tools\apache-maven-3.9.16\bin\mvn.cmd -DskipTests package

:: 4) 一键启动（Redis → 算法服务8001 → 后端8080）
cd .. && start_all.bat
```

访问：http://127.0.0.1:8080 （前端+后端） · http://127.0.0.1:8001/docs （算法服务文档）

### 8.3 一键启动说明（start_all.bat）

自动依次启动 Redis（tools 内置）、FastAPI 算法服务（三域+跨域模型启动约 10~30 秒）、SpringBoot 后端；前端产物已打包进 jar。如 `backend/target` 无 jar 会自动执行 Maven 构建；`frontend` 修改后需重新 `npm run build` 并重新打包。

## 10. 已知局限与展望

1. 课程域评分为基于真实课程目录的模拟数据（公开个体级 MOOC 评分需天池 MOOCCube 申请），替换真实数据只需重写 `preprocess_domain.py` 课程分支的字段映射。
2. 跨域评估采用相似配对模拟（离线数据无跨域用户），线上注册用户的真实跨域行为是该机制的实际应用场景，可在系统上线后做在线 A/B 验证。
3. 行为增量为"评分后全量重训"（秒级），生产环境应升级为 Flink/Spark 流式增量更新。
4. 推荐缓存按 (domain, algo, user, n) 粒度，行为变更即淘汰；高并发下可增加热门结果公共缓存层。
